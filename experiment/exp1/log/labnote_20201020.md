一、目标与背景
- 目标：在 q9_1 系列脚本中，将 QCBM 融合到 edge embedding，并支持按 PDB ID 加载训练用的碱基配对参考矩阵；同时保证数据读取与特征化过程在真实数据中的健壮性。
- 背景问题：
  - 训练中出现 UnicodeDecodeError（FASTA 文件含非 UTF-8 字节或非 FASTA 文件混入）。
  - 训练时出现 ValueError（广播报错），具体为坐标长度与序列长度不一致导致的张量形状不匹配。
  - base_map 与 alphabet 不一致（要求统一为 AUCG）。

二、代码修改概述（dev1.2 版本中的关键点）
- FASTA 解析鲁棒性（已在 dev1.2 中体现）
  - read_fasta_biopython 打开文件时使用 encoding='utf-8' 且 errors='ignore'，遇到非 UTF-8 字节不报错，尽量读取。
  - 当一个文件解析不到任何 FASTA 记录时，打印警告并跳过该文件。
- 参考矩阵加载（已在 dev1.2 中体现）
  - 引入 load_reference_matrix（from package_score.sequence_similarity_score）。
  - 在按 PDB ID 计算包评分的流程中尝试从 RNAdesignv1/train/matrices 加载对应的参考矩阵（支持 .mtx/.npy 以及大小写变体），若加载失败或形状不匹配，打印警告并回退到单位矩阵以保证流程不中断。
- featurize 函数修复长度不一致导致的广播错误（本次新增/修复）
  - 对每个样本计算 seq_len 与 coords_len，并取 eff_len = min(seq_len, coords_len) 作为该样本的有效长度。
  - 将坐标与序列索引都截断到 eff_len；以整批样本中的最大有效长度 L_max 进行 padding，避免 X[i,:,:,:] 赋值时的形状不匹配。
  - 当某样本序列长度与坐标长度不一致时，在训练日志中打印 Warning，并明确采用的截断长度。
  - 返回值保持原始序列长度数组 seq_lengths（用于下游兼容）。
  - 该修改对应文件中的 featurize 段落（约 172 行附近）。

四、问题成因与影响评估
- 序列与坐标长度不匹配的成因（真实数据常见）：
  - PDB/mmCIF 坐标缺失部分残基（FASTA 为完整序列）。
  - 坐标中存在插入码或额外处理导致长度偏差。
  - 数据预处理阶段存在轻微对齐偏差。
- 当前策略对训练影响：
  - 采用最小长度截断，使坐标与序列严格对齐，避免形状错误；对大多数样本而言，差异很小，对训练影响有限。
  - 警告仅用于提示该样本发生了对齐修正，属于预期行为。

五、结论
- UnicodeDecodeError 问题已通过鲁棒读取规避。
- 参考矩阵按 PDB ID 加载已实现，缺失时回退至单位矩阵并给出警告，保证评分流程不中断。
- 广播错误（形状不匹配）已通过 featurize 的对齐策略修复，训练正常推进。日志中的长度不匹配 Warning 属于正常现象。

六、后续建议（可选）
- 更严格的数据策略：
  - 过滤：对 |coords_len − seq_len| > 阈值（如 >10）的样本直接跳过，提升数据一致性。

  - 如序列出现 T/N 等，可在 featurize 中加入容错映射（T→U；N→A 或使用专用索引并掩码），避免潜在的 index 问题。
